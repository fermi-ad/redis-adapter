# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| 0.1.x | Yes |
| Unreleased snapshots | No guarantee |

Until the first stable major release, security fixes are made on `main` and
released in the current minor line when practical.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's
**Report a vulnerability** link on the repository Security page to send a
private report to the maintainers.

Include the affected revision, Redis deployment mode, reproduction steps,
impact, and any suggested mitigation. Do not include production credentials,
private hostnames, or operational data.

Maintainers will acknowledge the report, assess scope, and coordinate a fix and
disclosure timeline through the private report.
